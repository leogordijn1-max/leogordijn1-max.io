WPFW opdracht 1

Voor deze opdracht heb ik het fundament van mijn persoonlijke portfoliosite gemaakt. In deze blog beschrijf ik mijn aanpak, ontwerpkeuzes, problemen en wat ik tijdens de opdracht heb geleerd.

HTML CSS Flexbox CSS Grid Responsive
01

De opdracht

Voor deze opdracht moest ik een statische en responsive portfoliosite maken met minimaal drie pagina's: een Whoami-pagina, een projectenoverzicht en een blogoverzicht. De pagina's moesten via een werkende navigatie met elkaar verbonden zijn.

De website moest worden opgebouwd met semantische HTML5 en responsive CSS3. Daarnaast moest ik mijn ontwerpkeuzes onderbouwen aan de hand van minimaal twee gebruikersscenario's en kort de request/response-cyclus van een website uitleggen.

02

Mijn aanpak

Omdat ik nog relatief nieuw ben met HTML en CSS ben ik begonnen met het maken van de basisstructuur. Ik heb eerst de verschillende HTML-pagina's aangemaakt en deze met een navigatiebalk aan elkaar gekoppeld.

Tijdens het werken aan de website heb ik hulp en feedback gekregen van meerdere groepsgenoten. Zij hebben mij onder andere geholpen met tips voor de layout. Zo heb ik geleerd om een container te gebruiken om de content een maximale breedte te geven en netjes in het midden van de pagina te houden.

Ik heb daarnaast ChatGPT gebruikt voor uitleg en tips over HTML en CSS. Vooral bij technieken die voor mij nieuw waren, zoals Flexbox, CSS Grid, gradients en relatieve paden, heb ik uitleg gevraagd om beter te begrijpen hoe ik deze kon gebruiken.

Voor de vormgeving wilde ik een donkere website met meerdere kleuren. Samen met ChatGPT heb ik dit idee verder uitgewerkt. Uiteindelijk heb ik gekozen voor een donkere achtergrond met donkerblauwe en paarse kleuren.

Naar aanleiding van feedback ben ik de layout ook als ontwerp gaan uitwerken in Figma. Hierdoor kon ik beter bepalen waar onderdelen zoals de navigatie, teksten, afbeeldingen en kaarten moesten komen voordat ik deze verder uitwerkte met HTML en CSS.

03

Gebruikersscenario's

Scenario 1 — Een bezoeker wil weten wie ik ben

Een docent, medestudent of andere bezoeker komt op mijn portfolio en wil snel kunnen zien wie ik ben en wat ik doe. Daarom heb ik mijn Whoami-pagina als startpagina gebruikt. Mijn naam, opleiding en informatie over mijzelf zijn hier direct zichtbaar.

Vanuit de navigatie kan de bezoeker eenvoudig naar mijn projecten en blog. Ook gebruik ik een container zodat de content niet over de volledige breedte van een groot scherm wordt uitgerekt en de tekst overzichtelijk blijft.

Scenario 2 — Een bezoeker wil mijn werk bekijken

Een bezoeker wil kunnen bekijken aan welke projecten en opdrachten ik tijdens mijn opleiding heb gewerkt. Via de navigatie kan de bezoeker daarom direct naar mijn projectenoverzicht en blogoverzicht.

Op het projectenoverzicht kan de bezoeker informatie lezen over projecten die ik heb gemaakt en wat mijn eigen bijdrage hieraan was. In mijn blog kan de bezoeker meer lezen over mijn opdrachten, aanpak en gemaakte keuzes.

De informatie wordt op verschillende plaatsen in kaarten weergegeven. Hierdoor zijn verschillende onderdelen duidelijk van elkaar gescheiden en kan een bezoeker de pagina makkelijker bekijken.

04

Mijn ontwerpkeuzes

Vaste navigatie

Ik heb ervoor gekozen om op iedere pagina dezelfde navigatie te gebruiken. Hierdoor hoeft een bezoeker niet terug naar de startpagina om een ander onderdeel van mijn portfolio te openen. Dit helpt bij beide gebruikersscenario's, omdat informatie over mijzelf en mijn werk snel bereikbaar blijft.

Gebruik van kaarten

Voor verschillende onderdelen van mijn website gebruik ik kaarten. Hiermee worden teksten en opdrachten visueel van elkaar gescheiden. Dit helpt vooral bij het tweede gebruikersscenario, omdat een bezoeker mijn werk hierdoor makkelijker kan bekijken en verschillende onderdelen sneller van elkaar kan onderscheiden.

Kleurgebruik

Voor de uitstraling heb ik gekozen voor een donkere achtergrond met donkerblauwe en paarse kleuren. De tekst is voornamelijk licht zodat deze duidelijk zichtbaar blijft op de donkere achtergrond.

De paarse kleuren komen ook terug bij onderdelen zoals links, tags en borders. Hierdoor hebben de verschillende pagina's dezelfde uitstraling.

05

Technische keuzes

Voor de structuur van de website gebruik ik HTML en voor de vormgeving CSS. Ik heb geprobeerd semantische HTML-elementen te gebruiken, zoals nav, main, header, section, article en footer.

Voor verschillende onderdelen van de layout gebruik ik Flexbox. In mijn navigatie gebruik ik bijvoorbeeld display: flex om de navigatie-items naast elkaar te plaatsen.

Voor het blogoverzicht gebruik ik CSS Grid. Hiermee kan ik meerdere kaarten naast elkaar plaatsen zonder iedere kaart afzonderlijk te hoeven positioneren.

Alle pagina's maken gebruik van hetzelfde CSS-bestand. Hierdoor kan ik algemene onderdelen zoals de achtergrond, navigatie, kaarten en containers op één plek aanpassen.

06

Responsive design en toegankelijkheid

De website moet niet alleen op een computer werken, maar ook op kleinere beeldschermen. Daarom gebruik ik media queries in mijn CSS. Hiermee kan ik de layout aanpassen wanneer het scherm smaller wordt.

Op een kleiner scherm kunnen onderdelen die normaal naast elkaar staan onder elkaar worden geplaatst. De introductie op mijn Whoami-pagina kan bijvoorbeeld van een horizontale naar een verticale indeling veranderen.

Voor de toegankelijkheid gebruik ik een logische structuur met headings en geef ik afbeeldingen een duidelijke alt-tekst. Ook gebruik ik lichte tekst op de donkere achtergrond zodat de tekst duidelijk leesbaar blijft.

Door semantische HTML-elementen te gebruiken krijgt de HTML daarnaast meer betekenis en is de structuur van de pagina duidelijker.

07

Request/response-cyclus

Wanneer iemand mijn website bezoekt, stuurt de browser een HTTP-request naar de webserver voor de HTML-pagina die de gebruiker wil bekijken. De server stuurt deze pagina vervolgens terug in een HTTP-response.

Browser → HTTP Request → Webserver
Browser ← HTTP Response ← Webserver

Nadat de HTML is ontvangen, ziet de browser welke andere bestanden nodig zijn. Voor bestanden zoals style.css en afbeeldingen worden daarom aparte requests verstuurd.

Nadat deze bestanden door de server zijn teruggestuurd, gebruikt de browser de HTML voor de structuur, CSS voor de vormgeving en de afbeeldingen om uiteindelijk de volledige pagina weer te geven.

08

Problemen en oplossingen

Navigatie met float

In eerste instantie gebruikte ik float om een deel van mijn navigatie links en een deel rechts te plaatsen. Dit maakte de layout lastiger te beheren. Met hulp van ChatGPT heb ik geleerd hoe ik hiervoor Flexbox kon gebruiken.

De intro class

Bij mijn introductie gebruikte ik eerst een <intro>-element, terwijl mijn CSS naar .intro verwees. Ik heb hierdoor geleerd dat de punt in CSS naar een class verwijst. Ik heb dit daarom aangepast naar een semantisch HTML-element met class="intro".

Relatieve paden

Toen ik mijn blogpagina in een aparte blogs-map plaatste, werkten mijn CSS en navigatielinks niet meer. Ik heb hierdoor geleerd hoe relatieve paden werken. Met ../ kan ik vanuit de blogs-map één map teruggaan om bijvoorbeeld style.css te bereiken.

Layout

Het verdelen van de verschillende onderdelen over de pagina vond ik in het begin lastig. Meerdere groepsgenoten hebben mij hierbij tips gegeven. Vooral het gebruik van een container hielp om de content op verschillende pagina's op dezelfde manier uit te lijnen.

09

Wat heb ik geleerd?

Tijdens deze opdracht heb ik veel nieuwe basiskennis opgedaan over HTML en CSS. Vooral Flexbox, CSS Grid, containers, gradients, relatieve paden en responsive CSS waren technieken waar ik vooraf nog weinig ervaring mee had.

Ook begrijp ik nu beter waarom semantische HTML belangrijk is. In plaats van voor ieder onderdeel een div te gebruiken, kan ik met elementen zoals nav, section, article en footer duidelijker aangeven wat een onderdeel van de pagina betekent.

Daarnaast heb ik geleerd dat het handig is om eerst na te denken over het ontwerp voordat ik alles direct in HTML en CSS probeer te maken. Door eerst een globale layout te maken, weet ik beter waar ik tijdens het programmeren naartoe werk.

Ook heb ik gemerkt dat feedback en hulp vragen nuttig zijn. Meerdere groepsgenoten hebben mij geholpen met de layout en ik heb ChatGPT gebruikt om uitleg te krijgen over technieken die voor mij nog nieuw waren.

Bij een volgende website zou ik daarom eerder beginnen met een globaal ontwerp. Daarna zou ik eerst de HTML-structuur maken en vervolgens de CSS gebruiken om het ontwerp verder uit te werken.
