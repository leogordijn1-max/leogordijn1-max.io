WPFW Opdracht 1

Voor deze opdracht heb ik het fundament van mijn persoonlijke portfoliosite gemaakt. In deze blog laat ik stap voor stap zien hoe ik van het leren van de basis van HTML en CSS naar mijn uiteindelijke website ben gegaan.

HTML CSS Flexbox CSS Grid Responsive
01

Begin van de opdracht

Voor deze opdracht moest ik een statische en responsive portfoliosite maken. De website moest minimaal bestaan uit een Whoami-pagina, een projectenoverzicht en een blogoverzicht. Deze pagina's moesten met een werkende navigatie met elkaar verbonden zijn.

Aan het begin van de opdracht had ik nog weinig ervaring met HTML en CSS. Daarom ben ik eerst begonnen met het leren van de basis voordat ik de website verder ging uitwerken.

02

De basis van HTML en CSS leren

Mijn eerste stap was het leren en oefenen van de basis van HTML en CSS. Dit heb ik gedaan tijdens de lessen en door video's van Bro Code te bekijken.

Ik heb hierbij onder andere geleerd hoe een HTML-pagina is opgebouwd en hoe ik met CSS de vormgeving van een pagina kan aanpassen. Ook heb ik geleerd over onderwerpen zoals kleuren, het box model en verschillende manieren om elementen op een pagina te plaatsen.

Voor mijn kleuren ben ik HSL gaan gebruiken. Hiermee kan ik de hue, saturation en lightness van een kleur aanpassen. Ik ben vervolgens zelf gaan experimenteren met verschillende donkere kleuren en paarse accenten.

Tijdens het oefenen maakte ik eerst kleine onderdelen om te kijken hoe verschillende HTML-elementen en CSS-regels werkten. Daarna ben ik deze kennis gaan gebruiken voor mijn eigen portfolio.

03

Eerste versie van mijn website

Nadat ik de basis beter begreep, ben ik begonnen met de eerste versie van mijn website. Ik heb eerst de verschillende HTML-pagina's aangemaakt en een navigatie toegevoegd zodat ik tussen de pagina's kon wisselen.

In het begin gebruikte ik float om onderdelen van mijn navigatie naast elkaar te plaatsen. Dit werkte, maar ik merkte dat het lastiger werd om de elementen goed uit te lijnen.

Ook liep ik tegen problemen aan toen ik mijn blogpagina in een aparte map plaatste. Mijn CSS en links werkten toen niet meer zoals verwacht. Hierdoor heb ik geleerd hoe relatieve paden werken. Vanuit mijn blogs-map gebruik ik bijvoorbeeld ../ om één map terug te gaan.

04

Een ontwerp maken in Figma

Nadat ik eerst direct in HTML en CSS was begonnen, kreeg ik als feedback dat het handiger was om eerst beter na te denken over het ontwerp. Daarom heb ik mijn website verder uitgewerkt in Figma.

Bij het ontwerpen heb ik gekeken naar mijn gebruikersscenario's. Een belangrijke gebruiker van mijn portfolio is bijvoorbeeld een recruiter die snel wil kunnen zien wie ik ben, wat ik kan en aan welke projecten ik heb gewerkt. Daarom wilde ik de website overzichtelijk houden en ervoor zorgen dat de belangrijkste onderdelen makkelijk te vinden zijn.

Voor inspiratie voor mijn kleurgebruik heb ik gekeken op Mooiste Websites. Hier kwam ik de website van Audience Republic tegen. Deze website gebruikt voornamelijk donkergrijs, wit en paars en wordt omschreven als modern en minimalistisch. Dit vond ik goed passen bij de uitstraling die ik voor mijn eigen portfolio wilde.

Ik heb dit ontwerp niet overgenomen, maar wel gebruikt als inspiratie. Voor mijn eigen website heb ik daarom gekozen voor een donkere achtergrond, lichte tekst en paarse accenten. Ook gebruik ik afgeronde cards om verschillende onderdelen van de website duidelijk van elkaar te scheiden.

05

Het ontwerp uitwerken

Nadat ik mijn ontwerp verder had uitgewerkt, ben ik dit gaan toepassen in HTML en CSS. Hierbij heb ik geprobeerd mijn HTML logisch op te bouwen met semantische elementen zoals nav, main, header, section en footer.

Voor de layout gebruik ik voornamelijk Flexbox en CSS Grid. Flexbox gebruik ik bijvoorbeeld bij mijn navigatie en intro, omdat ik daar elementen naast elkaar wil plaatsen en makkelijk wil kunnen uitlijnen. Voor onderdelen met meerdere cards gebruik ik CSS Grid, omdat ik daarmee de content overzichtelijk over rijen en kolommen kan verdelen.

In het begin gebruikte ik op sommige plekken float om elementen naast elkaar te zetten. Later heb ik dit vervangen door Flexbox. Via MDN heb ik meer gelezen over Flexbox en Grid en begreep ik beter wanneer ik welke techniek kon gebruiken.

Voor kleinere onderdelen, zoals mijn skill-tags, gebruik ik Flexbox met flex-wrap. Hierdoor kunnen de tags automatisch naar een volgende regel gaan wanneer er niet genoeg ruimte is.

06

De website responsive maken

Ik wilde dat mijn portfolio niet alleen op mijn eigen laptopscherm goed werkt. Een recruiter of andere bezoeker kan de website bijvoorbeeld ook op een tablet of telefoon openen. Daarom heb ik mijn website responsive gemaakt.

Hiervoor gebruik ik Flexbox, CSS Grid en media queries. Op een groot scherm kunnen bijvoorbeeld meerdere cards naast elkaar staan. Wanneer het scherm kleiner wordt, worden dit minder kolommen en op een telefoon staan de cards uiteindelijk onder elkaar.

Voor meer informatie over responsive design en media queries heb ik MDN gebruikt. Tijdens het maken heb ik de website daarnaast op verschillende schermgroottes bekeken om te controleren of de content leesbaar bleef en er geen horizontale scrollbar ontstond.

07

Testen en verbeteren

Nadat de website grotendeels af was, heb ik verschillende controles uitgevoerd om te kijken wat ik nog kon verbeteren. Hiervoor heb ik onder andere de W3C HTML Checker en Google Lighthouse gebruikt.

Met een HTML-validator heb ik mijn HTML gecontroleerd. Hierbij kwam ik er bijvoorbeeld achter dat ik na een h1 direct een h3 gebruikte. Ik heb dit aangepast naar een h2 zodat de headingstructuur logisch blijft.

Met Google Lighthouse heb ik mijn website gecontroleerd op onder andere performance, toegankelijkheid, best practices en SEO. Hierbij heb ik onder andere gekeken naar het kleurcontrast en het gebruik van alt-teksten bij afbeeldingen.

Voor de toegankelijkheid van mijn kleurgebruik heb ik ook naar de WCAG-richtlijnen van W3C gekeken. Mijn website gebruikt lichte tekst op een donkere achtergrond. Ik heb gecontroleerd of er voldoende contrast tussen de tekst en achtergrond zit.

08

Request/response-cyclus

Wanneer een gebruiker mijn website opent, moet de browser eerst weten met welke server verbinding moet worden gemaakt. Hiervoor wordt via DNS de domeinnaam gekoppeld aan het bijbehorende IP-adres.

Met het IP-adres weet de browser waar de server bereikbaar is. Vervolgens kan er een verbinding worden gemaakt. Bij TCP wordt ervoor gezorgd dat de gegevens betrouwbaar tussen de browser en server worden verstuurd.

Browser → DNS → IP-adres → Server
Browser → HTTP Request → Webserver
Browser ← HTTP Response ← Webserver

De browser stuurt daarna een HTTP-request naar de webserver om de HTML-pagina op te vragen. De server stuurt deze terug met een HTTP-response.

Nadat de browser de HTML heeft ontvangen, ziet deze welke andere bestanden nodig zijn. Voor bijvoorbeeld style.css en afbeeldingen worden aparte requests verstuurd. Wanneer alle bestanden zijn ontvangen, kan de browser de pagina weergeven.

09

Feedback en verwerking

Tijdens deze opdracht heb ik meerdere keren feedback gekregen. Een van de eerste feedbackpunten was dat ik te snel direct in HTML en CSS was begonnen. Het advies was om eerst beter na te denken over het ontwerp. Daarom heb ik mijn ontwerp daarna verder uitgewerkt in Figma.

Ook kreeg ik feedback op mijn ontwerpkeuzes. Ik beschreef eerst voornamelijk wat ik had gemaakt, maar nog niet duidelijk welk probleem ik met een ontwerpkeuze wilde oplossen. Daarom ben ik mijn ontwerpkeuzes gaan beschrijven vanuit een probleem en een oplossing. Ook heb ik bronnen gekoppeld aan de keuzes die ik heb gemaakt.

Mijn eerste uitleg van de request/response-cyclus ging voornamelijk over HTTP. Ik kreeg als feedback dat ik hierbij ook onderdelen zoals DNS, IP en TCP moest meenemen. Daarom heb ik mijn uitleg uitgebreid zodat duidelijker wordt wat er gebeurt voordat een pagina in de browser verschijnt.

Daarnaast kreeg ik feedback dat ik mijn testresultaten beter moest aantonen. Daarom heb ik mijn website gecontroleerd met Lighthouse en de W3C HTML Checker en heb ik gekeken naar de verbeterpunten die daaruit kwamen.

10

Wat heb ik geleerd?

Aan het begin van deze opdracht had ik nog weinig ervaring met HTML en CSS. Tijdens het maken van mijn portfolio heb ik vooral geleerd door eerst de basis te leren en deze daarna zelf toe te passen en uit te proberen.

Ik begrijp nu beter wanneer ik verschillende technieken kan gebruiken. Flexbox is handig wanneer ik elementen in één richting wil plaatsen en uitlijnen. CSS Grid gebruik ik wanneer ik een duidelijk raster met rijen en kolommen wil maken. Ook weet ik nu beter wanneer flex-wrap handig is.

Daarnaast heb ik meer geleerd over responsive design, media queries, HSL-kleuren, relatieve paden en semantische HTML. Door mijn website te testen heb ik ook gezien waarom een goede headingstructuur, alt-teksten en voldoende kleurcontrast belangrijk zijn.

Een belangrijk punt dat ik meeneem naar een volgende opdracht is dat ik eerder over het ontwerp wil nadenken. In het begin begon ik vrij snel met programmeren. Door later eerst mijn ontwerp in Figma uit te werken, had ik een duidelijker beeld van waar ik met mijn HTML en CSS naartoe wilde werken.

11

Zelfstudie en AI-hulp

Voor deze opdracht heb ik in totaal ongeveer 10,5 uur aan zelfstudie besteed. Hiervan heb ik ongeveer 3 uur besteed aan het leren en oefenen van HTML en CSS, 4 uur aan het bouwen en vormgeven van mijn website, 1,5 uur aan het responsive maken en testen en 2 uur aan mijn blog en onderbouwing.

Tijdens de opdracht heb ik ook ChatGPT gebruikt. Ik heb dit voornamelijk gebruikt voor uitleg wanneer ik niet begreep hoe bepaalde HTML- of CSS-code werkte, voor het oplossen van problemen in mijn code en voor feedback op onderdelen die ik had gemaakt.

De uitleg heb ik gebruikt om mijn eigen code verder aan te passen. Hierbij heb ik geprobeerd te begrijpen waarom een oplossing werkt, zodat ik de gebruikte technieken en mijn keuzes zelf kan uitleggen.

12

Bronnen

Tijdens deze opdracht heb ik verschillende bronnen en hulpmiddelen gebruikt om HTML en CSS te leren en mijn website verder te ontwikkelen.

  • Bro Code: gebruikt voor het leren van de basis van HTML en CSS. Via deze video's heb ik onder andere meer geleerd over HTML-elementen, CSS en HSL-kleuren.
  • Mooiste Websites – Audience Republic: gebruikt als inspiratie voor de uitstraling en het kleurgebruik van mijn website.
  • MDN Web Docs: gebruikt om meer te leren over Flexbox, CSS Grid, media queries en responsive design.
  • Google Lighthouse: gebruikt om mijn website te testen op performance, toegankelijkheid, best practices en SEO.
  • W3C HTML Checker: gebruikt om te controleren of mijn HTML correct was opgebouwd en om fouten in mijn HTML te vinden.
  • ChatGPT: gebruikt voor uitleg over HTML en CSS, hulp bij problemen in mijn code en feedback op onderdelen van mijn website.
