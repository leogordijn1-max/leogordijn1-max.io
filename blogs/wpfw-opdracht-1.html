Mijn portfolio website

Voor deze opdracht heb ik het fundament van mijn persoonlijke portfoliosite gemaakt. In deze blog beschrijf ik mijn aanpak, ontwerpkeuzes, problemen en wat ik tijdens de opdracht heb geleerd.

HTML CSS Flexbox CSS Grid Responsive
01

De opdracht

Voor deze opdracht moest ik een statische en responsive portfoliosite maken met minimaal drie pagina's: een Whoami-pagina, een projectenoverzicht en een blogoverzicht. De pagina's moesten via een werkende navigatie met elkaar verbonden zijn.

De website moest worden opgebouwd met semantische HTML5 en responsive CSS3. Daarnaast moest ik mijn ontwerpkeuzes onderbouwen aan de hand van minimaal twee gebruikersscenario's en kort de request/response-cyclus van een website uitleggen.

02

Mijn aanpak

Omdat ik nog relatief nieuw ben met HTML en CSS ben ik begonnen met het maken van de basisstructuur. Ik heb eerst de verschillende HTML-pagina's aangemaakt en deze met een navigatiebalk aan elkaar gekoppeld.

Tijdens het werken aan de website heb ik hulp en feedback gekregen van meerdere groepsgenoten. Zij hebben mij onder andere geholpen met tips voor de layout. Zo heb ik geleerd om een container te gebruiken om de content een maximale breedte te geven en netjes in het midden van de pagina te houden.

Ik heb daarnaast ChatGPT gebruikt voor uitleg en tips over HTML en CSS. Vooral bij technieken die voor mij nieuw waren, zoals Flexbox, CSS Grid, gradients, transitions en relatieve paden, heb ik uitleg gevraagd om beter te begrijpen hoe ik deze kon gebruiken.

Voor de vormgeving wilde ik een donkere website met meerdere kleuren. Samen met ChatGPT heb ik dit idee verder uitgewerkt. Uiteindelijk heb ik gekozen voor een donkere achtergrond waarin blauwe en paarse kleuren geleidelijk in elkaar overlopen.

Naar aanleiding van feedback ben ik de layout ook als ontwerp gaan uitwerken in Figma. Hierdoor kon ik eerst bepalen waar onderdelen zoals de navigatie, teksten, afbeeldingen en kaarten moesten komen voordat ik deze verder uitwerkte met HTML en CSS.

03

Gebruikersscenario's

Scenario 1 — Een bezoeker wil weten wie ik ben

Een docent, medestudent of andere bezoeker komt op mijn portfolio en wil snel kunnen zien wie ik ben en wat ik doe. Daarom heb ik mijn Whoami-pagina als startpagina gebruikt. Mijn naam en informatie over mijn opleiding zijn hier direct zichtbaar.

Vanuit de navigatie kan de bezoeker vervolgens eenvoudig naar mijn projecten en blog. Ook gebruik ik een container zodat de content niet over de volledige breedte van een groot scherm wordt uitgerekt en de tekst overzichtelijk blijft.

Scenario 2 — Een bezoeker wil mijn werk bekijken

Een bezoeker wil kunnen bekijken aan welke projecten en opdrachten ik tijdens mijn opleiding heb gewerkt. Daarom heb ik het projectenoverzicht verdeeld in de categorieën Project, WPFW en Database.

Binnen iedere categorie worden de opdrachten als kaarten weergegeven. Hierdoor kan een bezoeker snel door mijn werk heen kijken zonder eerst een grote hoeveelheid tekst te hoeven lezen.

Op kleinere beeldschermen worden de kaarten anders verdeeld of onder elkaar geplaatst. Hierdoor blijft het overzicht ook op bijvoorbeeld een telefoon goed bruikbaar.

04

Mijn ontwerpkeuzes

Voor de algemene uitstraling wilde ik een donkere website maken, maar ik wilde niet dat de hele achtergrond uit één kleur zou bestaan. Daarom wilde ik meerdere kleuren gebruiken terwijl de algemene uitstraling donker bleef.

Samen met ChatGPT heb ik gekeken hoe ik dit idee kon uitwerken. Uiteindelijk heb ik gekozen voor een combinatie van donkerblauw en paars. Met gradients lopen deze kleuren geleidelijk in elkaar over en krijgt de achtergrond meer diepte.

De blauwe en paarse kleuren komen ook terug bij links, borders, tags en hover-effecten. De kaarten hebben een licht transparante achtergrond zodat ze zichtbaar losstaan van de achtergrond, maar wel binnen dezelfde stijl passen.

Voor de projecten en blogs heb ik kaarten gebruikt. Hierdoor zijn de verschillende opdrachten duidelijk van elkaar gescheiden en kunnen bezoekers makkelijker door de pagina heen kijken.

05

Technische keuzes

Voor de structuur van de website gebruik ik HTML en voor de vormgeving CSS. Ik heb geprobeerd semantische HTML-elementen te gebruiken, zoals nav, main, header, section, article en footer.

Voor verschillende onderdelen van de layout gebruik ik Flexbox. In mijn navigatie gebruik ik bijvoorbeeld display: flex en margin-right: auto om Home links te houden en de andere navigatielinks rechts te plaatsen.

Voor het projectenoverzicht gebruik ik CSS Grid. Hiermee kan ik meerdere kaarten naast elkaar plaatsen zonder iedere kaart afzonderlijk te hoeven positioneren.

Ook gebruik ik :hover en transition. Hierdoor veranderen kaarten en links geleidelijk wanneer de gebruiker er met de muis overheen gaat.

Alle pagina's maken gebruik van hetzelfde CSS-bestand. Hierdoor kan ik algemene onderdelen zoals de achtergrond, navigatie en containers op één plek aanpassen.

06

Responsive design en toegankelijkheid

De website moet niet alleen op een computer werken, maar ook op kleinere beeldschermen. Daarom gebruik ik media queries in mijn CSS. Hiermee kan ik de layout aanpassen wanneer het scherm smaller wordt.

Projectkaarten die op een groot scherm naast elkaar staan, kunnen op een kleiner scherm bijvoorbeeld onder elkaar worden geplaatst. Ook kan de introductie op de Whoami-pagina van een horizontale naar een verticale layout veranderen.

Voor de toegankelijkheid probeer ik een logische structuur met headings te gebruiken en geef ik afbeeldingen een duidelijke alt-tekst. Ook gebruik ik lichte tekst op de donkere achtergrond zodat er voldoende contrast is.

Door semantische elementen te gebruiken krijgt de HTML daarnaast meer betekenis en is de structuur van de pagina duidelijker.

07

Request/response-cyclus

Wanneer iemand mijn website bezoekt, stuurt de browser een HTTP-request naar de webserver voor de HTML-pagina die de gebruiker wil bekijken. De server stuurt deze pagina vervolgens terug in een HTTP-response.

Browser → HTTP Request → Webserver
Browser ← HTTP Response ← Webserver

Nadat de HTML is ontvangen, ziet de browser welke andere bestanden nodig zijn. Voor bestanden zoals style.css en afbeeldingen worden daarom aparte requests verstuurd.

Nadat deze bestanden door de server zijn teruggestuurd, gebruikt de browser de HTML voor de structuur, CSS voor de vormgeving en de afbeeldingen om uiteindelijk de volledige pagina weer te geven.

08

Problemen en oplossingen

Navigatie met float

In eerste instantie gebruikte ik float om Home links en de andere navigatie-items rechts te plaatsen. Dit maakte de layout lastiger te beheren. Met hulp van ChatGPT heb ik geleerd hoe ik hiervoor Flexbox kon gebruiken.

De intro class

Bij mijn introductie gebruikte ik eerst een <intro>-element, terwijl mijn CSS naar .intro verwees. Ik heb hierdoor geleerd dat de punt in CSS naar een class verwijst. Ik heb dit daarom aangepast naar een semantisch HTML-element met class="intro".

Relatieve paden

Toen ik mijn blogpagina in een aparte blogs-map plaatste, werkten mijn CSS en navigatielinks niet meer. Ik heb hierdoor geleerd hoe relatieve paden werken. Met ../ kan ik vanuit de blogs-map één map teruggaan om bijvoorbeeld style.css te bereiken.

Layout

Het verdelen van de verschillende onderdelen over de pagina vond ik in het begin lastig. Meerdere groepsgenoten hebben mij hierbij tips gegeven. Vooral het gebruik van een container hielp om de content op verschillende pagina's op dezelfde manier uit te lijnen.

09

Wat heb ik geleerd?

Tijdens deze opdracht heb ik veel nieuwe basiskennis opgedaan over HTML en CSS. Vooral Flexbox, CSS Grid, containers, gradients, transitions, relatieve paden en responsive CSS waren technieken waar ik vooraf nog weinig ervaring mee had.

Ook begrijp ik nu beter waarom semantische HTML belangrijk is. In plaats van voor ieder onderdeel een div te gebruiken, kan ik met elementen zoals nav, section, article en footer duidelijker aangeven wat een onderdeel van de pagina betekent.

Daarnaast heb ik geleerd dat het handig is om eerst na te denken over het ontwerp voordat ik alles direct in HTML en CSS probeer te maken. Door eerst een globale layout te maken, weet ik beter waar ik tijdens het programmeren naartoe werk.

Ook heb ik gemerkt dat feedback en hulp vragen nuttig zijn. Meerdere groepsgenoten hebben mij geholpen met de layout en ik heb ChatGPT gebruikt om uitleg te krijgen over technieken die voor mij nog nieuw waren.

Bij een volgende website zou ik daarom eerder beginnen met een globaal ontwerp. Daarna zou ik eerst de HTML-structuur maken en vervolgens de CSS gebruiken om het ontwerp verder uit te werken.
