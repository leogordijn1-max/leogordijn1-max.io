WPFW Opdracht 2

Voor deze opdracht heb ik mijn bestaande portfolio interactief gemaakt met JavaScript. In deze blog laat ik stap voor stap zien welke interactieve onderdelen ik heb toegevoegd en wat ik daarbij heb geleerd.

JavaScript DOM Events Form validation Fetch API
01

Begin van de opdracht

In de vorige opdracht had ik de basis van mijn portfolio gemaakt met HTML en CSS. De website was responsive en de verschillende pagina's waren met elkaar verbonden, maar er zat nog weinig interactie in de website.

Voor deze opdracht moest ik mijn bestaande website interactiever maken met JavaScript. Hierbij moest ik onder andere interacties toevoegen die de DOM aanpassen, een formulier valideren, content vanuit gestructureerde data weergeven en gegevens ophalen van een externe API.

Ik heb ervoor gekozen om deze onderdelen toe te voegen aan mijn bestaande portfolio in plaats van losse voorbeelden te maken. Hierdoor zijn de JavaScript-onderdelen ook echt onderdeel geworden van de website.

02

JavaScript toevoegen aan mijn portfolio

Voor de interactieve onderdelen heb ik een script.js-bestand gebruikt. Dit bestand koppel ik aan de pagina's waarop JavaScript nodig is.

Tijdens deze opdracht heb ik geleerd hoe JavaScript kan samenwerken met mijn HTML. Met bijvoorbeeld querySelector en querySelectorAll kan ik HTML-elementen vanuit JavaScript selecteren.

Vervolgens kan ik met addEventListener reageren op acties van een gebruiker, zoals het klikken op een knop of het versturen van een formulier.

Ik heb mijn JavaScript zoveel mogelijk verdeeld over functies met een eigen taak. Hierdoor staat niet alle code door elkaar en kan ik functies makkelijker opnieuw gebruiken of aanpassen.

03

Projecten vanuit JavaScript weergeven

Een van de eisen van de opdracht was om content vanuit gestructureerde data weer te geven. Hiervoor heb ik mijn projecten in een JavaScript-array gezet.

Ieder project is een object met eigenschappen zoals de titel, categorie, programmeertaal, beschrijving, mijn bijdrage en wat ik van het project heb geleerd.

Met de functie renderProjects() loop ik door deze projecten heen. Voor ieder project wordt met JavaScript een nieuw article-element gemaakt. De informatie uit het object wordt daarna in dit element geplaatst.

Hierdoor hoef ik de volledige HTML van ieder project niet handmatig op mijn projectenpagina te schrijven. Wanneer ik later een project wil toevoegen, kan ik een nieuw object aan de array toevoegen.

04

Projecten filteren

Nadat mijn projecten vanuit JavaScript werden weergegeven, heb ik een filter toegevoegd. Boven de projecten staan knoppen voor Alle, School en Persoonlijk.

Met addEventListener controleer ik op welke knop de gebruiker klikt. De waarde van data-filter wordt vervolgens gebruikt om te bepalen welke projecten zichtbaar moeten worden.

In de functie filterProjects() gebruik ik filter() om alleen projecten met de gekozen categorie over te houden. Daarna gebruik ik opnieuw renderProjects() om de juiste projecten op de pagina te tonen.

Op dit moment heb ik alleen een echt schoolproject in mijn portfolio. Om te controleren of het filter voor persoonlijke projecten ook werkte, heb ik tijdens het testen tijdelijk een persoonlijk testproject toegevoegd. Nadat ik had gecontroleerd dat het filter werkte, heb ik dit testproject weer verwijderd.

05

Mijn blog interactief maken

Ook op mijn blogoverzicht wilde ik JavaScript gebruiken. Bij iedere blog staat daarom een knop waarmee een bezoeker extra informatie kan openen en weer sluiten.

De extra informatie staat standaard verborgen met het hidden-attribuut. Wanneer de gebruiker op "Meer informatie" klikt, zoekt JavaScript eerst de juiste blog met closest().

Daarna wordt de extra informatie zichtbaar gemaakt en verandert de tekst van de knop naar "Minder informatie". Wanneer opnieuw op de knop wordt geklikt, wordt de informatie weer verborgen.

Hiervoor heb ik een aparte functie toggleBlog() gemaakt. Dezelfde functie kan daardoor voor meerdere blogs op het blogoverzicht worden gebruikt.

06

Contactformulier valideren

Voor mijn contactpagina heb ik een formulier gemaakt met de velden naam, e-mail en bericht. Met JavaScript controleer ik de invoer voordat het formulier als correct wordt beschouwd.

Hiervoor heb ik aparte functies gemaakt: validateName(), validateEmail() en validateMessage(). Iedere functie heeft één taak en controleert één invoerveld.

Een naam mag niet leeg zijn, het e-mailadres moet een geldig e-mailadres zijn en het bericht moet minimaal tien tekens bevatten. Wanneer een veld niet geldig is, wordt onder dat veld een foutmelding weergegeven.

Bij het versturen gebruik ik event.preventDefault(). Hierdoor wordt het formulier niet direct verstuurd en kan JavaScript eerst alle invoer controleren.

Wanneer alle drie de velden geldig zijn, verschijnt een bevestiging dat het bericht correct is ingevuld en worden de velden geleegd.

07

Toegankelijke feedback

Bij het contactformulier wilde ik niet alleen foutmeldingen laten zien, maar deze ook op een toegankelijke manier aan de invoervelden koppelen.

Hiervoor gebruik ik aria-describedby. Hiermee is bijvoorbeeld het naamveld gekoppeld aan de foutmelding die bij dat veld hoort.

Voor de algemene bevestiging van het formulier gebruik ik aria-live="polite". Hierdoor kan een screenreader een verandering in deze tekst doorgeven zonder dat de gebruiker zelf naar het bericht hoeft te navigeren.

Ik gebruik daarnaast novalidate op het formulier. Hierdoor gebruikt de browser niet zijn eigen standaard foutmeldingen, maar kan ik mijn eigen JavaScript-validatie en foutmeldingen laten zien.

08

Gegevens ophalen met een API

Een ander onderdeel van de opdracht was het ophalen van actuele of externe gegevens met een publieke API. Hiervoor heb ik de Wikipedia API gebruikt op mijn Whoami-pagina.

Op deze pagina vertel ik over SV Nootdorp, ADO Den Haag en Liverpool. Naast mijn eigen verhaal haal ik voor deze clubs aanvullende informatie op van Wikipedia.

In mijn HTML geef ik met een data-wikipedia-attribuut aan welke Wikipedia-pagina moet worden opgehaald. JavaScript leest deze waarde en gebruikt fetch() om de gegevens op te vragen.

Omdat het ophalen van gegevens tijd kan kosten, gebruik ik een async-functie en await. Uit het JSON-resultaat gebruik ik onder andere data.extract om een stukje tekst over de club dynamisch op de pagina te zetten.

Tijdens het laden staat er eerst een laadmelding op de pagina. Het ophalen van externe gegevens kan ook mislukken. Daarom staat de fetch() in een try/catch. Wanneer er een fout ontstaat, krijgt de bezoeker een foutmelding in plaats van een lege plek op de website.

09

Testen en verbeteren

Tijdens het toevoegen van JavaScript heb ik de verschillende onderdelen steeds afzonderlijk getest. Zo heb ik gecontroleerd of de projectfilters de juiste projecten tonen, of de bloginformatie geopend en gesloten kan worden en of het contactformulier ongeldige invoer tegenhoudt.

Bij het contactformulier heb ik bijvoorbeeld getest wat er gebeurt wanneer velden leeg zijn, wanneer een ongeldig e-mailadres wordt ingevuld en wanneer het bericht te kort is. Daarna heb ik ook gecontroleerd of bij geldige invoer de succesmelding verschijnt.

Bij de Wikipedia API heb ik gecontroleerd of de informatie voor alle drie de clubs wordt geladen en of er tijdens het laden een melding zichtbaar is.

Omdat hetzelfde script.js-bestand op meerdere pagina's wordt gebruikt, moest ik er ook rekening mee houden dat bepaalde HTML-elementen niet op iedere pagina bestaan. Bij het contactformulier controleer ik daarom eerst met if (form) of het formulier op de huidige pagina aanwezig is voordat ik een eventlistener toevoeg.

Hiermee voorkom ik dat JavaScript op andere pagina's probeert te werken met een element dat daar niet bestaat en daardoor een fout in de console veroorzaakt.

10

Feedback en verwerking

Nadat ik de interactieve onderdelen had toegevoegd, heb ik alle HTML-pagina's opnieuw gecontroleerd met de W3C HTML Checker. Hierbij kwamen nog enkele fouten en waarschuwingen naar voren. Zo gebruikte ik bij een afbeelding een backslash in het bestandspad en gebruikte ik een section zonder bijbehorende heading. Ik heb het bestandspad aangepast en de section vervangen door een div, omdat deze alleen voor de layout werd gebruikt. Na deze aanpassingen heb ik alle pagina's opnieuw gecontroleerd. Alle pagina's worden nu zonder fouten of waarschuwingen goedgekeurd door de W3C HTML Checker.

De ontvangen feedback voor deze opdracht en hoe ik deze heb verwerkt, voeg ik hier toe nadat ik de feedback heb ontvangen.

11

Wat heb ik geleerd?

Tijdens deze opdracht heb ik geleerd hoe ik JavaScript kan gebruiken om een statische website interactief te maken. Ik begrijp nu beter hoe JavaScript elementen uit de DOM kan selecteren en aanpassen.

Ook heb ik geleerd hoe eventlisteners werken en hoe ik functies kan gebruiken om mijn code op te delen. Bij mijn projecten heb ik daarnaast gewerkt met arrays, objecten, forEach() en filter().

Door het contactformulier heb ik meer geleerd over formuliervalidatie en toegankelijkheid. Ik heb gezien dat het niet alleen belangrijk is om ongeldige invoer tegen te houden, maar ook om duidelijk aan de gebruiker te vertellen wat er fout is.

Het werken met de Wikipedia API was voor mij een nieuwe stap. Hierdoor heb ik geleerd hoe ik met fetch() gegevens van buiten mijn eigen website kan ophalen en hoe ik met async, await en try/catch om kan gaan met het laden en mogelijke fouten.

Ik heb ook geleerd dat JavaScript-code niet alleen moet werken, maar dat het belangrijk is om de code overzichtelijk te houden. Door functies een duidelijke eigen taak te geven kan ik de code makkelijker begrijpen, testen en later aanpassen.

Bij de gegeven oplossingen heb ik geprobeerd te begrijpen wat de verschillende functies en JavaScript-methodes doen. Ik heb de code daarna toegepast en getest in mijn eigen website, zodat ik de werking ervan zelf kan uitleggen.
